# Fixes v0.3.2 — Lenient Numbers & Tolerant Mesh Snapshot Decoding
Feature: v0.3.2 Fixes in Rp-app
Status: Completed

## Specs
S1 Lenient Long Serializer (G1):
- Relay schemas declare timestamps and metrics (`startedAt`, `endedAt`, `durationMs`, `cost`, `at`, `createdAt`, `expiresAt`, `generatedAt`, `lastAt`, `lastCommAt`, `lastSeenAt`, `nextBefore`, `size`, `ts`) as `Type.Number()`, where floating-point numbers are valid JSON Schema.
- In `kotlinx.serialization`, standard `Long` parsing fails when encountering decimal numbers (e.g. `47725510.340108`).
- Implement `LenientLongSerializer` (and `@Serializable(with = LenientLongSerializer::class)`) that accepts:
  - JSON integers (e.g. `123456`)
  - JSON floating-point decimals (e.g. `47725510.340108` or `1.0`), rounding with `round half-up` (`Math.round(double)`) to Long.
  - Rejects non-number primitives (e.g. strings, booleans, objects).
  - Also support nullable variants `NullableLenientLongSerializer` where null is accepted.
- Apply to every field across the protocol that corresponds to `Type.Number` in Rp-relay.
- Audit table mapping field, Kotlin class, relay schema type, and fix.

S2 Mesh Snapshot Tolerant Item Decoding (G2):
- A decode failure inside a single `MeshNode`, `SubagentSummary`, `MeshEdge`, `MeshGroup`, or `MeshComm` must not fail the whole `MeshSnapshot`.
- Implement tolerant list deserialization or error boundary per item: if one element fails to decode, log it and discard/skip that element, retaining all other valid nodes/edges/subagents.
- Only show top-level error state if the root snapshot itself is unreadable.

S3 Test Coverage (G3):
- Test decoding exact failing subagent payload shape (`startedAt: 47725510.340108`, `tokens: 321595`, `turns: 9`).
- Test that a `MeshSnapshot` containing one malformed subagent/node still successfully decodes and renders the other nodes.
- Ensure all round-trip fixture contract tests (`FixturesTest`) remain green.

S4 Release v0.3.2:
- Bump `versionName` to `0.3.2` in `app/build.gradle.kts`.
- Update `README.md`, `docs/INSTALACION.md`, and `docs/QA.md`.
- Build release APKs from the final commit and verify signatures (`6a7ef9…`) and `aapt2 badging`.
- Run full gate and report `[v0.3.2 — READY FOR REVIEW]` via intercom.
